## カセット（神楽坂）

- `/kagurazaka/cassettes/artists`：アーティスト一覧（All・A〜Z・#）。アーティストを選ぶと作品一覧、作品を選ぶと詳細を表示します。`/kagurazaka/cassettes` はこの一覧へ転送します。
- `/kagurazaka/artists/:id/cassettes`：アーティスト別の作品一覧。レコードと同じ1列表示です。タイトル・アーティスト・A面/B面の1曲目による検索は共通ヘッダーの検索から利用できます。
- `/kagurazaka/admin/cassettes`：カセットの検索・ページ送り・アーティスト／いいね／補正込みスコアでの並べ替え。新規作成・作品情報の編集・削除と、読み・ふりがな・ランキング補正の更新ができます。
- `/api/sync-cassettes`：管理画面からのPOSTはログイン必須。CronからのGETは `CRON_SECRET` 必須。毎日13:10 JSTに同期します。

「神楽坂カセットテープリスト」の列順は、場所・番号・所有者・タイトル・アーティスト・A面１曲目・B面１曲目・コメントです。`Cassette` は店舗・場所・番号で識別します。場所と番号を維持すれば、タイトル修正や行の並べ替えでもID・いいねを維持します。場所や番号の変更は別のカセットとして扱います。

空行は無視します。場所・正の整数の番号・タイトル・アーティストが未入力または不正な行はスキップし、その同期では削除を保留します。場所・番号の重複、列構成の変更、有効データ0件では同期を中止します。同期はトランザクションで行い、カセット同士の並行同期をロックします。レコードの同期と保存先・履歴を分離しています。

管理画面で作品情報を追加・変更・削除した場合は、シートにも同じ変更を反映してください。次回同期ではシートの作品情報が優先されます（読み・ふりがな・ランキング補正は保持）。管理画面・同期のどちらで削除しても、そのカセットの特集掲載・いいね・ランキング補正を同時に削除します。同じ数値IDのレコード／トラックの特集掲載には影響しません。

リリース時は、新コードの起動前にカセット対応の4つのマイグレーションを対象環境へ適用し、デプロイ後に神楽坂管理画面の「カセットリスト同期」で初回取り込みを行います。既存のGoogleサービスアカウントと同じスプレッドシートを使います。

検証:

```sh
node --import tsx --test test/cassette-sheet.test.ts
# 全マイグレーション適用済みの、空のローカル検証DB（DB名は _test で終わるもの）を指定
CASSETTE_TEST_DATABASE_URL=postgresql://localhost/hub_cassette_test node --import tsx --test test/cassette-sync.integration.test.ts
```

カセットのアーティスト管理は `/kagurazaka/admin/artists?context=cassettes` から利用できます。アーティストの読み・ふりがなはレコード／トラックと共有します。ランキング補正は人気順・一覧・検索・特集・いいね操作後の表示に反映されます。リリース時は追加の `20261014010000_add_cassette_labels`、`20261014020000_cassette_management_parity`、`20261014030000_cleanup_cassette_feature_refs` も適用してください。最後のマイグレーションは、既に削除されたカセットの特集参照を除去します。

ビルド時の文言生成はDBの値を優先し、未登録のキーには `src/lib/label-defaults.ts` の初期値を使います。文言マイグレーション前でもビルドできますが、カセット機能の実行にはDBマイグレーションが必要です。
